## 기능 상세

### F-001 오늘
- 동작: 오늘 날짜(한국 시간)의 진행 · 지연 업무와 오늘 일지, 상태 표시줄의 오늘 투입 시간.
- 권한: 로그인한 본인 데이터만(RLS). 로그인은 ae:p 포털이 맡는다.

### F-002 업무 목록 · 휴지통
- 동작: 업무 제목 · 설명(Markdown) · 예정 기간 · 카테고리 · 태그 · 알람. 상태는 저장하지 않고 계산한다(삭제 > 완료 > 예정 > 지연 > 진행). 예상 진척은 예정 기간 중 영업일 경과 비율.
- 삭제는 휴지통(`deleted_at`) → 복원 또는 영구 삭제.

### F-003 업무 상세 · 일지
- 동작: 일지 추가 · 수정 · 삭제. 공수 = 투입 시간 합계(8시간 = 1MD). 가장 최근 일지의 진척률과 첫 · 마지막 일지 날짜가 DB 트리거로 업무에 반영된다.

### F-004 빠른 입력
- 입력: `#카테고리 내용 1h30m 60%`. 업무를 고르지 않고 `#카테고리`를 쓰면 당일 업무를 만들고 일지까지 기록한다.

### F-005 캘린더 · 일정
- 동작: 일요일 시작 월 · 주 · 일 보기, 업무 예정 · 개인 · 업무 일정 필터. 일정은 종일 또는 시간 지정, 업무 연결, 알람.

### F-006 주간 보고서
- 동작: 고른 주(월~일)의 일지를 카테고리별로 집계해 Markdown 보고서를 만든다. 공휴일은 영업일에서 뺀다.
- API: `GET /reports/weekly?date=YYYY-MM-DD&format=md|json` (사용자 토큰, RLS).

### F-007 알림 · 웹 푸시
- 동작: 웹은 🔔 패널 · 토스트. API 스케줄러(1분, service_role)가 알림을 만들고 아직 안 보낸 알림을 웹 푸시로 보낸다. 구독은 포털 계정 메뉴에서 한다.

### F-008 설정 · 카테고리
- 동작: 새 계정은 기본 카테고리 11개가 DB 트리거로 생긴다. 카테고리 · 알림 설정, 에이전트 잡 토큰(F-010).

### F-009 에이전트 모니터
- 동작: 화면을 열면 `POST /monitor/session`으로 세션 쿠키(15분)를 받고, 그 쿠키로 WebSocket 로그와 픽셀 오피스(`:8443`)가 열린다. 화면이 열려 있는 동안 10분마다 세션을 다시 받는다.
- 권한: 관리자(`app_metadata.role = 'admin'`)와, 포털 계정 관리에서 에이전트 공유를 켠 멤버(`app_metadata.agent_share = true`). 테스터 계정은 볼 수 없다.
- 공유 범위: 픽셀 오피스는 볼 수 있는 계정끼리 같이 본다. 로그 · 알림은 잡을 등록한 계정에만 간다.
- 예외: 볼 수 없는 계정은 세션 403 `agent_forbidden` → "에이전트는 관리자가 공유한 멤버만 볼 수 있어요" 안내. 공유를 끄면 늦어도 세션 쿠키가 끝나는 15분 안에 막힌다.
- 상태 받기(`POST /monitor/status`)는 잡 토큰 · 공용 토큰 · 같은 서버 요청으로 받는다. 공유를 끈 멤버의 잡 토큰도 계속 상태를 보낼 수 있다(토큰 폐기는 하지 않는다).

### F-010 에이전트 잡 토큰
- 출력: `kt1.<사용자 id>.<서명>` (DB 에 저장하지 않는다).
- 권한: F-009 와 같다. 볼 수 없는 계정은 403 → "에이전트는 관리자가 공유한 멤버만 쓸 수 있어요".

### F-011 배치 잡
- 동작: `jobs/run_stocks.py`(장중 시세, 장 마감 때 종가), `jobs/watch_openg.py`(개찰결과가 뜨면 COMPLETE 후 종료).

### F-012 테스터 계정 잠금 · 정리
- 대상: 포털의 공용 테스터 계정(`auth.users.raw_app_meta_data.role = 'tester'`).
- 잠금: [supabase/migrations/20261107000000_tester.sql](../../supabase/migrations/20261107000000_tester.sql) 의 트리거. 브라우저가 DB 를 직접 쓰므로 트리거로 막는다.
  - 기본 데이터(`tester_baseline_at` 이전에 만든 카테고리 · 업무 · 일지 · 일정)를 고치거나 지우면 "기본 데이터는 테스터가 바꿀 수 없어요"(오류 코드 AE401).
  - 테스터가 넣는 행의 `created_at`은 지금으로 고정된다. 테스터가 기본 업무에 일지를 쓰면 일지는 남지만, 진척률 · 실제 기간 재계산은 기본 업무를 고치지 않는다(트리거 안의 갱신은 기본 행이면 원래 값 유지).
  - 알림 · 푸시 구독은 잠그지 않는다(읽음 표시 가능). 서버(service_role)의 쓰기는 막지 않는다.
  - 편집 중(`tester_editing`)에는 잠금이 꺼지고, 정리는 편집을 시작하기 전(`tester_edit_started_at`)에 남은 데이터만 지운다.
- 정리: `POST /tester/reset`(포털이 로그아웃 직전에 부름, 사용자 토큰으로 자기 것만) · 매일 04:00(한국) `pg_cron` → `public.tester_reset`. 기준 시각 이후에 만든 일지 · 일정 · 업무 · 카테고리 · 알림 · 푸시 구독을 지운다. 테스터가 아니면 `{ deleted: 0 }`.
- 에이전트(F-009 · F-010)는 테스터에게 막혀 있다.
